Day in the life

A collector opens a case and sees the next step

A collector opens an overdue case at 95 days, with one email sent and no response. The case form shows AI Next Action tab with the suggested action (send_demand_letter), priority (high), and a plain-English rationale. The company has no AI provider configured, so the rationale is the deterministic one explaining the 90-day threshold and formal demand letter reason. The collector sends the demand letter. Later, the same case at 130 days shows refer_to_collections_agency because enough time has passed since the letter. If the collector logs a promise to pay (e.g. payment due in 30 days), the next read flips the suggestion to monitor (low priority) because the active promise suppresses further escalation.

Edge cases

The cases most modules quietly ignore.

In the shipped code today, each one a place where a cheaper module silently does the wrong thing.

PROMISE LIFECYCLE

Active promises, payment plans, disputes, holds, and resolved stages remain authoritative workflow controls. Provider prose cannot restart dunning on those cases.

DEMAND LETTER PROVENANCE

Manual letters and configured automated final notices stamp immutable demand-letter evidence. An existing letter routes to review rather than sending another; external referral needs a proved 30-day wait.

MATERIALITY

Write-off review uses exact overdue balance against company-currency materiality. Lower balances stay reviewable at medium priority; material balances receive high priority.

FAIL CLOSED

Missing, manual, failed, malformed, or control-suppressed providers raise a user-facing error and preserve existing narrative evidence byte-for-byte.

What is inside

Built to do the job, end to end.

  • Operational suggestions. Stored selection keys for action and priority support search, grouping, and sorting; rationale stays translated and deterministic with zero network I/O.
  • Provider evidence. One manager-confirmed case per request, row locking, exact source/provider fingerprint cache, actor/time/provider attribution, stale detection, and unforgeable server-only writes.
  • Escalation evidence. Manual letters and follow-up levels marked Treat as demand letter create immutable evidence consumed by the 90/120-day ladder.
  • Regressions. Live tests cover workflow controls, materiality, timezone boundaries, automated letters, duplicate-send prevention, ACLs, RPC forgery, provider cache, stale evidence, and metadata truth.

Honest about the edges

What this does not do, so nothing surprises you.

  • Suggestions never execute collection, write-off, legal, or agency action. A responsible person still reviews evidence and policy.
  • Provider refresh is deliberately synchronous, manager-only, singleton, and explicit. Form/list reads never invoke provider network I/O.
  • Historic automated notices created before demand-letter provenance existed are not guessed. Manual letter rows are safely backfilled; other legacy evidence remains fail-closed.
  • External letters must be logged as Letter so the waiting-period evidence exists. Custom automated final notices must enable Treat as demand letter.
